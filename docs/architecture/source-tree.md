# Source Tree

Crate-responsibility map for the Lorica workspace. This document
deliberately stops at crate / top-level-module granularity: per-file
enumerations drift on every release (the v1.0 version of this file
was flagged stale by two audits). For the exact current layout,
`ls <crate>/src/` is authoritative; `docs/BUMP-CHECKLIST.md` lists
every file that pins the product version; `CHANGELOG.md` records
architectural moves per release.

## Product crates (follow the product version)

| Crate | Responsibility |
|-------|----------------|
| `lorica` | The binary. `main.rs` is dispatch only; `cli.rs` holds the clap surface (including the `--automation-listen` / `--automation-listen-any` binds and their validator) plus the `worker`, `rotate-key`, `unban`, `upgrade`, `cluster`, `automation` and `mcp` subcommands; `cli_client.rs` is the loopback management-API client every credential-taking subcommand shares (one trust decision, one login contract, passwords from a file, stdin or the environment but never argv), `cli_cluster.rs` implements `cluster init / join / leave / status / break-glass / token`, `cli_automation.rs` implements `automation token create` and holds the one mint request both token commands send, `cli_mcp.rs` implements `mcp token create --tier`, a front end over it that reads the MCP tier table; `startup/` holds the three run modes (`supervisor.rs`, `worker.rs`, `single.rs`), the shared background-task helpers (`mod.rs`, audit H-9: one source of truth per spawn cluster) and one file per launch path that is not a run mode: `automation.rs` (what must hold before the automation socket opens), `cluster_plane.rs` and `cluster_follower.rs` (the two cluster roles), `telemetry_drain.rs` (the follower's telemetry push), `environment_reaper.rs` (the sweep for expired automation environments), `hot_upgrade.rs` (the zero-downtime binary handoff); `proxy_wiring.rs` + `proxy_wiring/` hold the data plane (see below); `capture/` the request-capture engine (`rules.rs` compiled predicates, `buffers.rs` the per-request byte buffers, `node_ceiling.rs` the node-wide memory ceiling those buffers reserve from so a diagnostic cannot become a memory-exhaustion primitive, `rule_budgets.rs` the per-rule total and sampling rate, `self_disable.rs` the off-request-path counter writes that disarm a rule which spent its total, `record.rs` the single JSON document a capture produces, `redact.rs` the header and query-parameter redaction applied before it leaves the proxy, `sink.rs` the outputs it leaves through); `health.rs` the active health loop (each backend at its own interval, the HTTP, TCP connect and TCP send/expect probes, the closed `ProbeFailure` reasons the failure counter and the down alert carry); `reload.rs` config/cert hot-reload; `bot.rs`/`bot_rdns.rs` bot-protection stash + rDNS; `ai_bot.rs` + `ai_bot/vendor_ips/` the AI-crawler registry and its checksum-verified vendor CIDR bundles; `connection_filter.rs`, `geoip.rs`, `mtls.rs`, `otel.rs` what their names say. |
| `lorica-config` | SQLite `ConfigStore` (per-entity submodules under `src/store/`, migrations under `src/migrations/`), config models (`src/models/`), encryption-at-rest helpers (`crypto.rs`). Sole DB access point for configuration. It also owns every shape that crosses a process or a node boundary: `canonical.rs` is the byte-stable snapshot encoder (`CANONICAL_FORMAT_VERSION = 3` since v1.11.0, strict decode) that cluster replication and drift detection hash, and its `restrict_for_recipient` cuts a follower's blob down to the routes and streams that node is targeted by plus their backends, certificates, capture rules and environments, so an edge never holds the rest of the fleet's upstreams and secrets; `models/stream.rs` is the layer-4 stream model (Epic 12): `Stream` and `StreamBackend` with their validation and the canonical UUID id rule, `binds_here` (the one statement of which node binds a stream: a follower what it is targeted by, the control plane only streams with an empty selector, a standalone node every enabled stream), `check_backend_attachments` (the UDP-only, portless and environment-owned backend rules every write path calls), and the closed `StreamEndReason` set; `models/health_check.rs` is the typed backend health check, its write-time validation and the custom-check limits, and `HealthCheck::reconcile`, the one place it is made to agree with the deprecated `health_check_path` column a rolled-back 1.10.6 still reads; `listen_ports.rs` is the one reserved-port and listen-address rule the CLI's listener validation, the stream API's per-node port check and the stream bind share (`ReservedPorts`, `clash`, the dual-stack `listen_addresses_conflict`, `stream_port_conflicts`); `store/streams.rs` holds the stream and stream-link CRUD, checked writers for the management API and unchecked ones for the replica apply and the import, which check the whole snapshot first; `export.rs` / `import.rs` are the TOML backup round-trip, with secrets replaced by `**REDACTED**` on the way out and re-import refused while the placeholder is still there; `diff.rs` previews per entity what an import would change; `connection_filter.rs` is the one CIDR parser every address list in the workspace answers to (TCP pre-filter, capture rules, automation tokens, both listeners); `route_selection.rs` is the one statement of which route serves a host and path (exact name, then wildcards most specific first, then the catch-all `_`, longest path prefix at each level), which the proxy's snapshot and the automation plane's write guard both read, and of the one form a host name is stored and compared in (`canonical_hostname`: ASCII lowercase, no trailing dot, since v1.10.2); `ai_crawler_registry.rs` holds the built-in crawler descriptors and the shared `robots.txt` builder. |
| `lorica-api` | Management plane: axum router + `AppState` (`server.rs`), per-domain handler modules, `routes/` (the route resource split by sub-feature: path rules, header rules, traffic splits, forward auth, mirror, mTLS, response rewrite, cert export), `middleware/` (sessions, rate limit, RBAC, metrics bearer, request span), `management_tls.rs` (the TLS material the localhost listener serves on, and the served-certificate record the CLI pins), `target.rs` (the guards each shared `_as` write body runs inside its store closure, unbounded from the dashboard and built from the token's grants on the automation plane), `preview.rs` (`?dry_run=true`: the same write body run to the row it would store and stopped before the store), `streams.rs` (stream CRUD at the route role floors, management plane only, and `first_port_conflict`, the per-node port check every stream write and the configuration import and its preview run under the store lock, answering `409 stream_port_conflict`), `acme/` (issuance / renewal handlers, challenge store, pending manual-DNS state - the pure protocol core lives in `lorica-acme`), `db.rs` (blocking-pool store access, audit H-3), `audit.rs` (the hash-chained audit log and its verifier), `log_store.rs` + `log_writer.rs` (persistent access/WAF logs + batched background writer, backlog #24), `log_sinks/` (fan-out of those same events to an external syslog collector, lossy by design so a slow collector never blocks a request), `metrics.rs` (data-plane counters + `/metrics` handler, built on `lorica-metrics`). Two surfaces here are not the dashboard. `automation/` is the second HTTPS listener added in v1.8.0, whose only credential is a scoped bearer token: `listener.rs` (its own socket, TLS and pre-authentication budgets), `auth.rs` (a minted static token or a GitLab ID token, the mode picked by the value's shape and never by the caller), `oidc/` (the RS256-pinned JWT verifier, its JWKS cache and replay protection), `scope.rs` (the whole authorization matrix in one fail-closed function), `audit.rs` (a row for every request, refusals included), `router.rs` (`whoami`, and `route_table`, the declared route table both automation routers are built from and the OpenAPI drift gate, the scope tests and the admin-tier sweeps read), `environments.rs` (the idempotent review-environment resource, one transaction per `PUT`), `read.rs` and `write.rs` (the v1.9.0 read and write surfaces the MCP server is built on, each a wrapper over the management handler; `write.rs` enforces every rule the plane adds to a write, the rules themselves declared in `lorica-automation-policy`), `protections.rs` (the predicates that weigh a row against the one-way rules, and which of them are in force on a route), `records.rs` (the route protection records: what a route a token deleted, or moved off a name, served there, held against later writes), `displacement.rs` (what a route write would take requests from, the stored routes and the records in one index built through `route_selection`, and how a token's row is refused or an environment's raised to them), `redact.rs` (the values the plane withholds from those views and the write-back of a withheld value; its module doc is the list), `mcp.rs` (the Streamable HTTP binding of the MCP server). Tests through the router follow the same split: `src/tests.rs` drives the management router, and each automation surface has its own file beside its module, `automation/tests.rs` (the Story 10.3 chain), `read/plane_tests.rs`, `write/plane_tests.rs`, `write/admin_tier_tests.rs` (the settings write of the admin tier), `write/record_tests.rs` (the route protection records end to end, from the token's delete to the operator's clear), `mcp/plane_tests.rs` and `environments/tests.rs`, sharing the fixtures in `automation/test_support.rs`; `plane_tests` because `read.rs`, `write.rs` and `mcp.rs` keep their inline unit `tests` modules. `cluster/` holds the fleet registry handlers plus `boundary.rs`, what this crate adds around the `lorica-fleet` runtime: the conversion of its error to `ApiError`, the audited detached unit and the certificate push the issuance paths call. `automation_tokens.rs` and `oidc_issuers.rs` administer those credentials from the MANAGEMENT plane on purpose, so no automation token can widen its own scope or mint a successor; `route_protection_records.rs` is the operator's side of the records, the listing, the clear and the clearing an operator's route write does. `capture.rs` serves capture-rule CRUD, `capture_ring.rs` the in-memory ring of the last records this process emitted (it lives here, not beside the record type, because the record type is in the `lorica` binary crate which depends on this one). |
| `lorica-acme` | Pure ACME / Let's Encrypt core, extracted from `lorica-api` in v1.6.0 (backlog #42a): the `instant-acme` protocol driver (HTTP-01, automated + manual DNS-01), CSR generation, its own `AcmeError`, and the DNS-01 provider challengers (Cloudflare, OVH, Route53 behind the `route53` feature). No dependency on the management API. |
| `lorica-metrics` | Shared Prometheus registry + type-safe registration helpers + cross-worker counter aggregation, extracted from `lorica-api` in v1.6.0 to break the `lorica-api -> lorica-bench` / `lorica-notify` cycle. Re-exports `prometheus` so consumers never depend on it directly. |
| `lorica-cluster` | Cluster plane (Epic 9): the authenticated, encrypted transport a control plane and its followers speak over mutual TLS 1.3. A protobuf message set disjoint from the worker plane's (`messages.rs`, `frame.rs`) riding the same pipelined RPC endpoint with WAN-tuned `limits.rs`; version-range negotiation and the schema-ordering check (`version.rs`, `handshake.rs`); the cluster CA, EKU-split leaf issuance and CRL minting (`ca.rs`, `certs.rs`, `tls.rs`); pre-authentication budgets and the per-source gate (`preauth.rs`, `challenge.rs`) in front of the two `listener/` sockets (enrollment and operational); join tokens, redemption and convergence admission (`token.rs`, `enroll.rs`, `admission.rs`); the follower `dialer.rs`; the in-memory `roster.rs` with its `session.rs` registry and kill switches; the confused-deputy `bridge.rs`; configuration `replication.rs` and telemetry fan-in (`telemetry.rs`). |
| `lorica-waf` | WAF engine: rule set, evaluation (`engine/`), IP blocklist, event types. |
| `lorica-notify` | Alert events + notification channels (stdout, email, webhook, slack). |
| `lorica-bench` | Passive SLA collection, active probes, load-test engine + scheduler. |
| `lorica-dashboard` | Svelte 5 frontend (`frontend/`) embedded into the binary via `build.rs` + rust-embed; serves the SPA and the CSP header. |
| `lorica-challenge` | Bot challenges: PoW + image captcha generation, verdict cookie HMAC. |
| `lorica-geoip` | GeoIP / ASN MMDB resolvers with hot-swappable process-wide handles. |
| `lorica-shmem` | Cross-worker shared-memory region: an anonymous memfd the supervisor creates and every worker maps (`region.rs`), holding two lock-free atomic hashtables of 64-byte slots, each a key, a counter and a last-update timestamp (`table.rs`). `waf_auto_ban` holds each client's WAF violations; `rate_counters` holds per-window counts (`window.rs`): each client's rate-limit violations per minute and the proxy's requests per second, for the rate-limit auto-ban and the flood defence. The supervisor evicts slots idle for five minutes (`eviction.rs`); keys are SipHash-1-3 under a key drawn per region (`hash.rs`). The rate-limit token buckets are not here: the authoritative ones live on the supervisor, synced with each worker's local cache over the worker RPC. |
| `lorica-mcp` | Management MCP server (Epic 11), a library and the `lorica-mcp` binary: the hand-rolled JSON-RPC core (`server.rs`, `jsonrpc.rs`), what the policy crate's tier table means for the catalogue (`tier.rs`: a tier's tools, the one registry rule, the scopes a tier mints), the tool catalogue (`tools.rs`), the untrusted-data fence every answer is built through (`untrusted.rs`), the stdio adapter and the HTTPS client it reaches the plane with (`stdio.rs`, `http.rs`, `config.rs`). The registry is built from a token's one tier and scopes, once at startup over stdio and per request over Streamable HTTP. It binds no socket of its own; the remote transport is a path on the `lorica-api` automation listener, and `lorica-api` depends on this crate, never the reverse, so the stdio binary carries no SQLite. |
| `lorica-automation-policy` | The automation plane's policy as data and pure functions, no I/O, `serde` its only dependency: the scope vocabulary (`scope.rs`, `AutomationScope` and the `settings:write` lifetime ceiling), the MCP tier table and the rule resolving a scope set to one tier (`tier.rs`), the admin settings allowlist (`settings.rs`), the withheld route fields, the one-way protection rules and the rule that keeps a custom health-check payload off every token (`protections.rs`), and the catalogue of named TCP health-check templates (`health_templates.rs`, `TCP_CHECK_TEMPLATES`), the whole set of bytes a token can make a probe send. `lorica-config`, `lorica-api`, `lorica-mcp` and `lorica` read it; the dashboard reads the tier table through the fixture `lorica-api/tests/automation_scope_fixture.rs` renders from it, and the template catalogue and the custom-check limits through `health-check-templates.generated.ts`, which `lorica-api/tests/health_check_template_fixture.rs` renders, with the marked section of `docs/health-checks.md`, and refuses when stale. |
| `lorica-adcs` | AD CS enrollment client (Epic 13): turns a CSR into an issued certificate through the authority's Certificate Enrollment Web Service, WS-Trust (MS-WSTEP) over SOAP 1.2 and HTTPS, authenticated with Kerberos SPNEGO bound to the TLS channel. It owns ticket acquisition, the channel binding, the SPNEGO exchange, the envelope and response parsing, chain extraction, CSR construction and the `krb5.conf` renderer. A leaf crate: its one first-party dependency is `lorica-tls`, for the outbound HTTP TLS policy, and it holds nothing of the store, routes or dashboard; the GSS-API FFI surface (`libgssapi`) lives here and nowhere else. When to issue, renew and store belongs to `lorica-api`. |
| `lorica-fleet` | Fleet runtime (backlog #52, v1.11.0), between the transport and its two consumers: it depends on `lorica-cluster` and `lorica-config` and on neither `lorica-api` nor `lorica`. `runtime.rs` is what this process is in the fleet (the control-plane and follower runtimes, the store-first roster/CRL refresh and its coalescer, drift, revocation, and the detached units a committed change runs in, with the panic hook through which `lorica-api` writes the audit row a panicking unit owes); `telemetry_store.rs` is the control plane's separate fan-in database, deliberately off the local log store so fleet-wide write volume is not a latency input to local dashboard and audit queries; `ingest.rs` decides what the control plane stores of one telemetry push, deterministic given the quota state, while the I/O around it stays in `lorica/src/startup/cluster_plane.rs`. Not part of `lorica-cluster` on purpose: the transport treats the replicated blob as opaque bytes and must not depend on `lorica-config`. |
| `lorica-stream` | Stream data plane (Epic 12, v1.11.0): layer-4 listeners served outside Pingora, on a runtime of their own. It depends on `lorica-worker` (the stream control messages, so a worker and single-process mode speak one type) and `lorica-config` (the stream model and its end reasons), and on neither `lorica-api` nor `lorica`. Worker side: `runtime.rs` is the `StreamRuntime`, a dedicated `lorica-stream` thread with its own tokio runtime that applies `attach` / `detach` / `refresh` / `quiesce` and answers each; `transport.rs` is its control channel (the `SOCK_SEQPACKET` end of a worker, or an in-process channel in single-process mode); `listener.rs` the TCP accept and UDP receive loops, one per socket; `handler.rs` the `StreamHandler` and `DatagramHandler` traits the TCP and UDP engines implement; `tracker.rs` the connection tracker that drains connections and closes them at their deadline with an end reason; `table.rs` the stream snapshot new accepts read. Supervisor side, all pure: `reconcile.rs` the diff between the streams a node binds and the bindings it holds, which also refuses an overlapping UDP binding the kernel would accept; `budget.rs` the fd budget that keeps streams off the HTTP reserve, and the budget view types; `state.rs` the bind-state registry the API, the audit chain and the fleet view read. `tests/runtime.rs` drives the runtime over real sockets. |

## `lorica/src/proxy_wiring/` (data plane, backlog #7 layout)

| Module | Responsibility |
|--------|----------------|
| `proxy_wiring.rs` (root) | `LoricaProxy` struct, spawn helpers, cache statics, the `ProxyHttp` trait impl (request_filter orchestration, upstream_peer, response filters, logging), public re-exports. |
| `config.rs` | `ProxyConfig` / `RouteEntry` / smooth-WRR state, route-table construction, `find_route`. |
| `filters.rs` | The request_filter stage methods (`check_*`, audit H-8) + `write_error_response` (audit H-10) + WAF event persistence hand-off. |
| `lb.rs` | Peak-EWMA tracker, per-(route, backend) circuit breaker. |
| `context.rs` | Per-request `RequestCtx`. |
| `worker_rpc.rs` | Worker-side RPC: two-phase config reload, metrics report. |
| `engines.rs` | Mode-switching engines (local vs supervisor-RPC: rate limit, verdict cache, breaker). |
| `rate_limit.rs` | Token-bucket identity (which limit a request draws from, the bucket key) and both ends of the worker-mode `RateLimitDelta` sync: the worker's batch and reply handling, the supervisor's authoritative buckets. |
| `ai_bot_merged.rs` | The AI-crawler snapshot the request path reads: the built-in registry seeded once, then the enabled custom rows layered on top (a custom row wins on name collision, so an operator can ship a fresh vendor CIDR list mid-cycle). Built per config snapshot and never panics on bad operator data. |
| `helpers.rs`, `error_pages.rs` + `error_pages.html`, `forward_auth.rs`, `mirror_rewrite.rs`, `bot_handlers.rs` | Shared pure helpers, error-page rendering and its `include_str!`-ed template, forward-auth client, request mirroring + response rewriting, bot solve/captcha handlers. |
| `tests.rs`, `cert_reload_commit_tests.rs`, `ai_bot_reload_tests.rs` | Unit + regression tests for the above. |

The traffic-capture hook has no module of its own here: it attaches
directly in `proxy_wiring.rs` at four points, because those are the
stages that see the bytes. Admission at `request_filter` (a node with
no capture rule pays one length check), request bytes at
`request_body_filter`, response bytes at `response_body_filter`, then
release and record emission at `logging`, where the record is built
from the same values as the access-log row. Everything it calls lives
in `lorica/src/capture/`.

## Forked crates (Pingora forks)

`lorica-core`, `lorica-proxy`, `lorica-http`, `lorica-error`,
`lorica-tls`, `lorica-lb`, `lorica-cache`, `lorica-memory-cache`,
`lorica-lru`, `lorica-ketama`, `lorica-limits`, `lorica-timeout`,
`lorica-pool`, `lorica-runtime`, `lorica-header-serde`, pinned at
0.1.0, and `tinyufo`, which keeps its own upstream version, preserve
upstream Pingora structure to stay rebaseable. `lorica-tls`
additionally carries the native cert resolver + OCSP stapling, and
`http_client.rs`, the rustls configuration every outbound reqwest client
of the workspace is built on (provider, protocol versions, trust roots).
`lorica-worker` and `lorica-command` are first-party process/IPC crates
and follow the product version, bumped with the product per
`docs/BUMP-CHECKLIST.md`, not the forked-crate 0.1.0 pin. Each crate's
`version` in its `Cargo.toml` is the authority.

## Tests

Test files mirror the source tree: unit tests live in
`#[cfg(test)]` modules beside the code (or sibling `*_tests.rs`
files for large regression suites), integration tests in each
crate's `tests/`, end-to-end Docker suites in `tests-e2e-docker/`,
frontend tests beside their components (`Foo.svelte` /
`Foo.test.ts`). A new test goes in the same directory layout as the
code under test.

## Packaging

`dist/` holds the `.deb` and `.rpm` build scripts (`build-deb.sh`,
`build-rpm.sh`), the RPM spec (`rpm/lorica.spec`), and the hardened
systemd unit
(`lorica.service`). THREE Dockerfiles must list every workspace
member: `Dockerfile` (release), `Dockerfile.dev` (dev image) and
`tests-e2e-docker/Dockerfile` (the image the Docker e2e suite builds).
A missing `COPY` breaks `cargo build --workspace` in Docker. The e2e
one is the easy miss because it lives in a subdirectory: `lorica-acme`
was absent from it for the whole v1.6.0 cycle and only surfaced when
`./tests-e2e-docker/run.sh` failed at build time. Treat them as a
trio, and touch all three in the commit that adds a crate.
(`ci-check.Dockerfile` is not part of the trio: it copies the whole
context and needs no per-crate line.)
